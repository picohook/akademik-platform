## 26 Ekim kesintisinin kök nedeni — **düzeltilmiş**

Önceki kayıtlar (`2026-10-26-v131.md`, `DEPLOY.md`, `HANDOFF`) "satır sabit
`libedge-v131` yazıyordu, `LIBEDGE_IMAGE` kullanılmıyordu" diyordu. **Yanlıştı.**

**Doğrusu:**

1. Satır **zaten** `${LIBEDGE_IMAGE:-akademik-platform:libedge-r2}` idi — değişken
   kullanılıyordu, **hiç verilmiyordu**. Compose varsayılana, yani eski
   `libedge-r2` imajına düştü.
2. **`sudo` değişkeni siler.** `LIBEDGE_IMAGE=... sudo docker compose` biçimi
   çalışmaz: `sudo` varsayılan olarak ortamı temizler (`env_reset`), değişken
   compose'a ulaşmaz. "Değişkeni verdim ama etkisi olmadı" tablosu tam olarak budur.

**Doğru kullanım:** değeri `.env.r2` içine yaz (compose `env_file: [.env.r2]` ile
okur), ya da `sudo LIBEDGE_IMAGE=... docker compose` /
`sudo --preserve-env=LIBEDGE_IMAGE`.

`--force-recreate` hiçbir durumda çözmez: container'ı yeniler, **imajı değiştirmez**.

## Rollback

Yalnızca `.env.r2` içindeki imaj adını çevir — compose dosyasına dokunma:

```bash
sudo sed -i 's/^LIBEDGE_IMAGE=.*/LIBEDGE_IMAGE=libedge-v131/' .env.r2
sudo sed -i 's/^APP_VERSION=.*/APP_VERSION=131/' .env.r2
sudo docker compose -f docker-compose.prod.yml -f docker-compose.libedge.yml \
  --env-file .env.production --env-file .env.r2 up -d --no-deps web
```

**Dikkat:** v130'a kadar inmek `r2://` anahtarlarını okuyamaz (`storage.mjs:45`,
`R2 asset requires R2 configuration`). Migration'lar geri alınmaz: `018`/`019`/`020`
ileri yönlüdür ve v131 koduyla da uyumludur.
