## Image-heavy 500 MB fixture

For a realistic image/raster test (not a random-byte dummy):

```bash
cd spike/app
python scripts/make-image-pages.py 188 ../../tmp/image-pages
node scripts/make-image-pdf.mjs ../../tmp/image-pages ../../tmp/large-500mb.pdf
```

188 noisy 1600×2200 JPEGs (quality 85) produce roughly 500 MB; the PDF has the same page count and embeds each image once. Upload it as a librarian and open with `?perf=1`. This is synthetic noise, so JPEG/decode cost is worst-case; a real scanned book is usually smaller per page.

Generated fixture (2026-10-22): `tmp/large-500mb.pdf`, **500,640,062 bytes**, **188 pages**, image-only (no text layer). Node/PDF.js legacy baseline: document load **4,549 ms**, first-page text 87 ms (0 chars), 20 page texts 187 ms. Browser cold-cache measurement is still required; at 20 Mbps a full 500 MB transfer would take ~200 s, so this test depends on PDF.js range requests fetching only the first-page image. If it fails, the acceptance target must be set with the real publisher file, not synthetic noise.

## Large-file baseline — 2026-10-22

> DevTools custom throttling units: **20 Mbps = 20,000 kbps**. If the profile field is set to `20`, it is 20 **kbps**; a 706 KB PDF then takes ~283 s (observed 317 s), which is not a reader regression.

Synthetic text PDF generated by `scripts/make-large-pdf.mjs` (no images; not the 500 MB P3):

- **File:** `tmp/large-2000.pdf`, 706 KB, **2,000 pages**, text layer.
- **Node/PDF.js legacy:** document load **662 ms**; first-page text **86 ms**; 20 page texts **338 ms**.
- **Browser (v86, localhost):** PDF load **1,495 ms**, first page **2,185 ms**, 8 renders avg **115 ms** (max 638 ms), last canvas 25 ms/text 6 ms, heap **16 MB**, zoom 130%.
- **Browser (v87, localhost, warm worker/cache):** PDF load **336 ms**, first page **491 ms**, 8 renders avg **27 ms** (max 112 ms), last canvas 9 ms/text 3 ms, heap **39 MB**, zoom 115%. **Cold-open target <2 s met in this run.**
- **Browser (v87, resumed at page 39/2000, warm-ish):** PDF load **1,071 ms**, first visible page **1,638 ms**, 20 renders avg **46 ms** (max 479 ms), last canvas 8 ms/text 3 ms, heap **27 MB**, zoom 115%. **<2 s target met again.**
- **Browser (20 Mbps custom, page 20/2000, cache disabled):** PDF load **1,729 ms**, first visible page **1,960 ms**, 20 renders avg **33 ms** (max 197 ms), last canvas 12 ms/text 8 ms, heap **4 MB**, zoom 78%. **Pass, but only 40 ms margin.** v89 prefetches the 1.9 MB PDF worker during idle to improve the cold-open margin.
- **Browser (v89, 20 Mbps, 3 cold-cache runs, page 20/2000):** first page **1,647 / 1,614 / 1,404 ms** (median **1,614 ms**); PDF load **1,383 / 1,274 / 1,129 ms**; 20 renders avg **43 / 30 / 29 ms** (max 226 / 278 / 243 ms); heap **4 / 7 / 7 MB**; zoom 78%. **All <2 s; render max <300 ms.**
- **v87 tuning:** canvas DPR capped at **1.5** (was 2); books >1,000 pages start at **115%** instead of 130% (`initialScaleCap`). Explicit fit/zoom still uses true fit.
- Need a **cold-cache** repeat (new browser profile / disabled HTTP cache) and a **500 MB image-heavy** file before calling P3 passed.
- The 500 MB image-heavy fixture is still missing; use a real publisher file for P1/P2/P3 rows.
- Scroll mode now creates lightweight page wrappers first and only adds canvas/text/highlight DOM when a page approaches the viewport (`createScrollPane` + `ensureScrollPaneElements`).

## Scaffold measurement — 2026-10-20

Not a formal P1/P2/P3 run; localhost, uncontrolled network, no RSS sampling.

- **File:** Oral Radiology: Principles and Interpretation, 63.6 MB, 697 pages, text layer.
- **Browser:** Chrome on Windows (devicePixelRatio not recorded).
- **Zoom:** initial fit 160%; later 73% during the 100-page run.
- **Cache:** not controlled; PDF.js document load 330–965 ms across runs.

| Metric | Result | Threshold | Status |
|---|---|---|---|
| Cold first page | 3.1–3.6 s | < 2 s | **Fail** |
| PDF document load | 330–965 ms | — | — |
| Page render average (100 pages) | 179 ms | p95 < 300 ms | p95 not measured; average passes |
| Page render max | 924 ms | — | cold page |
| Last page canvas / text | 113 / 94 ms | — | — |
| JS heap after 100 pages | 308 MB | RSS < 500 MB | heap, not RSS; stable from 286 MB at 20 pages |
| Heap after 20 pages | 22–286 MB | — | `performance.memory` varies with GC timing |
| Highlight alignment | not measured | ±3 px | open |

**Conclusion:** page-turn cost and memory are acceptable for a 63 MB / 697-page book; **cold first page misses the <2 s target**. The 100-page heap is essentially flat (286 → 308 MB), so no page-cache leak was observed.

**Next optimization:** first-page progressive paint (low-res canvas first, then fit-scale) or a lower initial fit cap for large PDFs. Re-run with the 500 MB fixture before signing off the PDF architecture.

**Progressive-paint attempt (v31, reverted in v32):** low-resolution first paint at 100% took 3,546 ms; full 130% took 3,830 ms. The 284 ms gap is too small to justify the flash. Cold first-page cost is font/document work, not canvas resolution; keep the loading overlay and full render instead.

**`disableFontFace` attempt (v33, removed in v34):** first page 4,070 ms, 20-page average 686 ms, last canvas 1,313 ms. Font paths made rendering substantially worse, not better; rejected.
